## 一、工程层级及资料边界

统一管理入口为「基础功能 / 工程资料目录」，按以下层级组织：

```text
区块
└─ 井场
   └─ 井（物理井身份）
      └─ 井眼（主井眼、导眼、侧钻等）
         ├─ 设计成果 → 业务修订 → 来源文件 / 轨迹数据快照
         └─ 实测成果 → 业务修订 → 来源文件 / 测斜数据快照
```

目录同时支持工程节点管理、原件导入与关联、测点查看、完整/增量/复测版本导入、差异对比、当前版本选择、施工状态及数据导出。工程树用于选择管理范围，右侧提供对应范围的实际管理操作。旧「井与测斜数据」入口跳转到该目录，不再保留第二个平行菜单。

来源文件的 `Project/Site/Well/Wellbore/Design` 原值仅作为来源元数据保存；工程目录和权限范围只使用区块、井场、井和井眼，不以来源文件夹替代工程实体。

## 三、文件、成果修订和数据快照

| 对象 | 身份与存储 | 操作规则 |
| --- | --- | --- |
| 原始文件对象 | `data_file`，SHA256、字节、对象路径 | 原件下载不改内容；归属修正不要求移动原件字节 |
| 来源登记 | `drilling_source_document`，来源路径、解析状态、来源元数据 | 同一路径同一内容重复导入复用来源记录；保留来源冲突 |
| 源表提取 | `drilling_source_extraction`，工作表/表格定位 | 一份文档可以提取多张表；保留各表定位 |
| 设计/实测成果 | `drilling_engineering_node`中的PLAN/SURVEY节点 | 同一井眼下分开设计与实测，备选方案可独立建成果节点 |
| 业务修订 | `drilling_engineering_revision` | 保存来源修订标签、阶段、说明及关联数据；无修订号时明确标识未知 |
| 不可变轨迹快照 | `drilling_survey_version`、`drilling_trajectory_version`及测点表 | 完整、增量、复测均保存新快照，旧测点不覆盖 |
| 当前选用版本 | `drilling_trajectory_head`，按井眼和DESIGN/ACTUAL分别维护 | 由工程人员明确发布；不按最大MD、测点数或文件时间自动选择 |
| 文件表示及版次 | `drilling_engineering_document_file` | 同一业务修订可以有多种文件表示；不同格式不自动视作后续修订 |

双48-45YH4的两份不同内容井斜表继续保留独立快照；文件名含“4235米”不等于其实际末测点深度或修订序号。相同源文档中提取的多张轨迹表归于对应井眼的同一来源修订，不按表张数伪造业务修订。

历史导入造成的重复关系使用规范关联标记折叠展示，历史关联ID仍保留。历史误建的双45-48YH4、米45-30、麒35物理井记录归档并记录`drilling_well_alias`；麒35导眼井眼仍是有效工程对象。迁移未删除轨迹快照或测点。为满足旧表`(well_id, version_no)`唯一约束，迁移麒35导眼数据时调整了3个快照的内部展示序号；快照ID保留，旧编号见首次迁移报告的`legacy_version_numbers`及迁移前备份。

## 五、核查方法与记录

1. 逐份比对132份原始文件、解析清单、数据库哈希及实际归档字节。
2. 按上述8组独立核对井场—井关系，核对麒35导眼/麒35H侧钻及2250 m来源参数。
3. 检查两套数据不存在跨井场父节点、成果/数据井眼不一致、PLAN/SURVEY用途错配、当前头错配、重复有效井/井眼节点及未折叠重复文件关联。
4. 对两套数据重复导入，检查来源、快照、测点、当前头、工程节点及资料关联是否稳定；另在临时空库和临时文件目录执行首次导入及重复导入。
5. 使用实际运行系统验证目录、数据版本、复测入口、工程节点管理、已有井眼引用、跨井共用原件及桌面/移动端页面。验证账号和临时库验证后清理。
