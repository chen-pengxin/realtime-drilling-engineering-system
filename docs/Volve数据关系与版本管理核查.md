# Volve 数据关系与版本管理核查

核查日期：2026-11-15。

## 一、正式工程层级

Volve 文件中的 `Project`、`Site`、`Well`、`Wellbore`、`Design` 是来源资料字段。系统正式工程树只使用：

```text
区块（15/9）
└─ 井场（Volve F 或 15/09-Loke C）
   └─ 井（F-1、F-10、F-11 等）
      └─ 井眼（F-1 A、F-1 B 等）
         ├─ 设计成果
         └─ 实钻测斜成果
```

`SLEIPNER`、`Q0015 SLEIPNER` 等来源工程名称不会创建系统工程节点，也不参与权限范围、邻井筛选或任务归属。它们随来源文件写入 `metadata_json`，用于回溯原始文档身份。

## 二、资料归属规则

- `15/9` 是来源中明确的区块标识，登记为区块；`Volve F`、`15/09-Loke C` 分别登记为井场。
- `F-1` 是物理井，`F-1 A` 是该井的井眼。字母井眼不能拆成新的物理井。
- `Design` 只表示设计成果的业务用途；`PLAN` 与 `ACTUAL` 分别建立设计成果和实钻测斜成果，不互相覆盖。
- 救援井位置或候选规划保留为来源文件及设计成果，不能自动登记为已钻物理井。
- 目录名与正文页眉冲突时，保留原始路径和冲突证据，解析后的身份需人工确认后才能用于计算。

## 三、文件与数据版本

原始字节进入 `data_file`，按 SHA256 复用；来源登记进入 `drilling_source_document`；表格、工作表和文本定位进入 `drilling_source_extraction`。这些对象都带 `field_id`，不带工程项目字段。

设计和实测分别保存在 `drilling_trajectory_version` 与 `drilling_survey_version` 中。完整导入、增量导入和复测都形成不可变新版本，旧测点不覆盖。井眼分别维护 `DESIGN` 和 `ACTUAL` 的 `drilling_trajectory_head`，当前版本由工程人员明确发布，不能按最大 MD、测点数或文件时间自动选择。

同一成果的 PDF、TXT、Excel 表示通过 `drilling_engineering_document_file` 关联；不同格式不会被误判为新的业务修订。来源修订标签、阶段、测量日期、导入日期和发布状态分别保存。

## 四、验证边界

导入和核查脚本使用 `field_id` 查询，校验以下约束：

1. 工程节点不存在 `PROJECT`、`SITE` 类型。
2. 井只能位于井场范围，井眼只能挂在对应物理井下，设计/实测成果只能挂在对应井眼下。
3. 来源文件、测点快照、当前版本和工程成果的井场与井眼关系一致。
4. 重复导入复用文件和版本，不复制原件或测点。

数据集文件夹名称和来源 Project 字段可以在文件详情中查看，但不会出现在正式工程层级选择器中。
