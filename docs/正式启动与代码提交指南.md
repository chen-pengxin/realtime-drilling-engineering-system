# 正式启动与代码提交指南

## 1. 适用范围

本指南适用于从 GitHub 获取实时钻井工程系统、在本机验证系统管理功能，以及把系统管理前后端代码提交到个人功能分支。`main` 是集成分支，不直接提交。

## 2. 获取代码

```bash
git clone git@github.com:chen-pengxin/realtime-drilling-engineering-system.git
cd realtime-drilling-engineering-system
git switch -c feat/system-management
```

如果已经克隆过仓库：

```bash
git switch main
git pull --ff-only origin main
git switch -c feat/system-management
```

## 3. 环境要求

准备 JDK 17、Maven 3.9+、Node.js 22+、npm、Python 3.11+、MySQL 8.0+。Docker 方式还需要 Docker Desktop；本地方式需要 MySQL 服务已启动。算法 Python 依赖包含仓库内固定 `wellpath-engine-1.0.0` wheel，不需要访问私有算法仓库。

## 4. Docker 完整启动

```bash
cp deploy/.env.example deploy/.env
```

编辑 `deploy/.env`，为 MySQL、MinIO 和回调令牌设置本机私有值。不要把 `deploy/.env` 提交到 Git。然后执行：

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up --build
```

Compose 在第一个空的 `mysql-data` 卷中自动执行：

1. `database/bootstrap/ruoyi-base.sql`：RuoYi 系统表、系统管理菜单和默认管理员；
2. `database/migrations/V1__...sql` 到最新迁移：钻井领域表和权限结构；
3. `test-case-import`：把仓库内 A/B/C 合成输入登记到工程资料目录；
4. `frontend-build`：运行 `npm ci` 和 `npm run build:prod`，把 `dist` 写入 Docker 卷；
5. Nginx：提供前端页面并代理 Java API。

浏览器访问 `http://localhost/`，使用 `admin / 123456` 登录。首次登录会要求修改密码。A/B/C 是测试区块下的演示井场，不是生产资料。

停止服务：

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml down
```

保留数据库卷时不要加 `-v`。只有确认要删除本机测试数据时才使用 `down -v`。

## 5. 本地开发启动

先创建数据库并导入结构：

```bash
export MYSQL_DATABASE=ry
export MYSQL_USER=root
export MYSQL_PASSWORD='本机密码'
./deploy/init-local-db.sh
```

安装依赖并构建：

```bash
python3 -m venv algorithm-server/.venv
(cd algorithm-server && .venv/bin/python -m pip install -r requirements-dev.txt)
(cd ruoyi-vue3 && npm ci)
(cd ruoyi-java && mvn -DskipTests package)
```

启动三项服务：

```bash
./deploy/local.sh start
```

启动脚本默认使用算法服务 `8000`、Java `8080`、Vite `5173`，并自动导入 A/B/C。浏览器访问 `http://127.0.0.1:5173/`。
默认账号：
账号：admin
密码：123456或者admin123
修改 Java 或 Vue 后执行：

```bash
./deploy/local.sh restart --build
```

查看和停止：

```bash
./deploy/local.sh status
./deploy/local.sh stop
```

## 6. 启动检查

启动后检查：

```bash
curl -fsS http://127.0.0.1:8000/health
curl -I 'http://127.0.0.1:8080/captcha/captchaImage?type=math'
curl -I http://127.0.0.1:5173/login
```

登录后应能看到系统管理菜单、实时大屏和三个工程任务入口。工程资料目录中应能看到“测试区块”以及测试案例 A、B、C；每个案例包含 10 口井，每口井有实钻和设计轨迹版本。

## 7. 系统管理功能提交范围

系统管理功能包括用户、角色、菜单、部门、岗位、字典、参数配置、数据权限、个人中心、登录与密码策略、运行监控和审计页面，以及对应 Java 控制器、服务、Mapper、SQL 迁移和前端页面。工程算法、轨迹数据、算法服务和生产数据不应被改写到该功能分支中。

提交前执行：

```bash
git status --short
git diff --check
(cd ruoyi-java && mvn -pl ruoyi-admin -am test)
(cd ruoyi-vue3 && npm run build:prod)
```

如果修改了数据库结构，新增一个幂等的 `database/migrations/Vxx__description.sql`，并在空库上按顺序测试，不修改已有迁移文件。

## 8. 安全检查与推送

提交前确认以下内容不在暂存区：`.env`、密码、数据库导出、`uploadPath/`、原始井斜资料、模型权重、日志、`target/`、`node_modules/`、`dist/`。使用明确文件或交互式暂存，不使用未经检查的 `git add .`。

```bash
git add -p
git diff --cached --check
git status --short
git commit -m "feat: implement system management"
git push -u origin feat/system-management
```

推送后把 Pull Request 地址发给项目负责人。不要向 `main` 直接推送，也不要使用 `git push --force`。项目负责人负责审查、解决冲突和合并。

## 9. 常见问题

- `npm ci` 报缺少 lock 文件：确认当前分支包含 `ruoyi-vue3/package-lock.json`，再执行 `npm ci`。
- Compose 报 `ry_20260319.sql` 不存在：使用当前仓库版本；初始化脚本路径是 `database/bootstrap/ruoyi-base.sql`。
- MySQL 已有表而初始化停止：先备份；如果是专门的空测试库，删除测试库后重试。不要对生产库设置 `INIT_ALLOW_EXISTING=YES`。
- 页面 404 或 `No static resource drilling/...`：浏览器访问前端端口，不能把 Vue 路由地址直接访问 Java 静态资源端口。
- 验证码无法加载：先确认 Java `8080` 健康响应，再刷新前端；验证码由 Java 生成，不由 Python 算法服务生成。
