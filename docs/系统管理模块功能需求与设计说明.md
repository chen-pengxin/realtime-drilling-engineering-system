# 实时钻井系统管理功能开发任务书

## 一、任务目标

负责完成实时钻井系统的系统管理前端和 Java 后端。

系统管理要解决账号安全、人员权限、工程数据访问范围、统一显示规则、平台运行状态和操作追溯问题。请结合本项目的工程使用场景调研若依已有能力，选择适合本项目的页面和交互方式，不要把若依全部功能机械搬入系统。

本任务书只规定必须完成的功能范围和业务目标，具体控件、页面布局、接口组织和技术实现方式由实施人员调研后确定，并保持若依后台的使用习惯。

## 二、必须完成的功能模块

### 1. 登录与账号安全

实现：

- 账号 ID和账号名称登录；
- 图形验证码和登录失败控制；
- 系统管理员创建账号，系统不开放注册；
- 系统自动生成唯一账号 ID，账号 ID不可修改；
- 账号名称可修改但必须唯一；
- 系统管理员、工程师、游客三类账号等级；
- 初始密码和管理员重置密码后的强制修改；
- 账号停用、启用、锁定和解锁；
- 游客有效时间、演示功能范围和只读限制；
- 会话超时、退出登录和异常会话失效。

游客只能访问测试演示数据，不能接触正式区块、井场、井、井眼、文件、轨迹版本和真实任务结果。

### 2. 用户、部门和岗位管理

实现：

- 用户查询、分页、排序、批量启停和批量删除；
- 用户账号、账号等级、部门、岗位、状态和最近登录信息维护；
- 管理员重置密码；
- 部门树维护；
- 岗位维护；
- 用户与部门、岗位的关联；
- 删除前检查关联关系；
- 停用部门、岗位或用户后的权限影响处理。

部门和岗位只用于人员组织，不得替代区块、井场、井、井眼工程层级。

### 3. 角色、菜单和功能权限

实现：

- 系统管理员、工程师、游客基础角色；
- 自定义工程师角色；
- 角色启停、成员查看和权限修改；
- 目录、页面、按钮三级菜单权限；
- 菜单排序、图标、显示和隐藏；
- 页面权限与按钮权限分离；
- 权限变更记录；
- 后端接口权限校验。

导航必须保证系统中只有一个首页、一个钻井工程入口和一个系统管理入口。防碰评价、姿态预测、轨迹再规划等工程模块应作为工程菜单权限配置，不在系统管理中复制页面。

### 4. 工程数据权限

实现工程数据范围授权，授权对象使用以下工程树：

~~~text
区块 → 井场 → 井 → 井眼
~~~

需要支持：

- 按区块授权；
- 按井场授权；
- 按井授权；
- 按井眼授权；
- 上级节点一键勾选下级节点；
- 批量选择、取消、搜索和查看完整路径；
- 全部井场、本部门、本部门及下级、指定井场、仅本人等范围；
- 角色范围和用户实际范围查看；
- 后端按井场范围过滤工程请求。

系统管理不创建和维护工程树，只保存人员或角色与工程范围的授权关系。系统中不得保留“项目”作为工程权限层级。

### 5. 工程业务显示字典

实现面向本项目的统一显示字典，重点解决不同工程页面名称不一致的问题。

至少包括：

- 数据来源；
- 文件格式；
- 轨迹资料类别；
- 井眼施工状态；
- 任务状态；
- 来源确认状态；
- 风险等级；
- 工程单位；
- 用户等级；
- 数据权限类型；
- 系统通知类型。

每个字典项应能说明使用它的业务页面。系统固定含义的编码不能被任意改写；历史记录正在使用的字典项不能直接删除，只能停用。停用后不得用于新增业务，历史数据仍显示原名称。

字典管理只维护显示名称、排序、启停和选择项，不负责修改误差模型、分离系数、扫描步长、求解器、轨道约束或预测模型参数。

### 6. 平台参数和主题管理

实现系统级显示和运行参数管理，包括：

- 系统名称和浏览器标题；
- Logo、登录页图片和浏览器图标；
- 默认首页；
- 日期、时间和时区显示；
- 默认分页和表格密度；
- 页面缓存、面包屑和标签页显示；
- 会话时长、验证码有效期和登录失败策略；
- 临时文件保留策略；
- 平台主题方案和用户界面偏好。

主题设置应支持项目负责人确认后的界面方案，并保证菜单、表格、按钮、文字和背景具有清晰对比度。主题设置不能改变工程风险颜色和轨迹图例的业务含义。

不要在平台参数页面混入工程计算参数。工程算法参数由工程功能负责人维护。

### 7. 系统通知

实现系统级通知，用于：

- 系统维护；
- 账号安全提醒；
- 功能更新说明；
- 数据导入规则说明；
- 系统运行异常提示。

实现通知草稿、发布、撤回、查询、阅读状态和已读记录。系统通知不替代实时防碰报警，工程报警仍由工程模块展示。

### 8. 日志、审计和在线会话

实现：

- 登录成功和失败记录；
- 账号、角色、菜单、数据权限变更记录；
- 字典、平台参数和主题变更记录；
- 公告发布和撤回记录；
- 文件导出、权限拒绝和管理员操作记录；
- 在线用户查询；
- 其他会话强制退出；
- 登录失败账号解锁。

日志至少能够追溯操作人、操作对象、操作时间、结果和请求来源。密码、验证码、令牌、原始文件内容和完整算法输入不得写入日志。

### 9. 系统服务和资源监控

实现平台运行状态查看：

- Java 后端；
- MySQL；
- Python 算法服务；
- 前端服务；
- 实时连接服务；
- CPU、内存、磁盘和 JVM；
- GPU 名称、利用率、显存、温度、功耗和训练可用状态；
- 服务心跳、响应延迟和异常摘要；
- 后台预测、训练和再规划任务的运行数量与异常状态。

监控页面只展示系统状态，不在系统管理中修改工程算法配置，也不代替实时大屏。

### 10. 数据安全和备份管理

系统管理需要具备基本的数据安全能力：

- 查看数据库、工程文件和模型文件的备份状态；
- 查看最近备份时间、备份范围和备份结果；
- 管理备份保留周期；
- 由管理员发起备份；
- 对恢复操作进行二次确认和权限限制；
- 记录备份、恢复和失败操作；
- 恢复前提示影响范围，禁止覆盖正在使用的数据而不经确认。

备份管理不提供任意 SQL 执行，不允许在页面直接删除数据库。

### 11. 个人中心

实现当前用户个人资料和安全设置：

- 查看账号 ID；
- 修改账号名称；
- 修改手机号、邮箱和头像；
- 修改密码；
- 查看自己的角色和工程数据范围；
- 查看登录记录；
- 修改个人主题和界面偏好；
- 退出其他设备。

个人中心不能修改账号等级、角色权限和工程数据授权。

## 三、系统管理与工程功能的职责边界

系统管理负责：

- 谁可以登录；
- 谁可以看到哪些菜单；
- 谁可以操作哪些按钮；
- 谁可以访问哪些井场；
- 页面中的业务名称和显示规则；
- 平台主题和通用参数；
- 系统服务状态；
- 管理操作追溯和数据备份。

工程功能负责：

- 区块、井场、井、井眼资料；
- 文件上传、解析和版本；
- 设计轨道和实钻测斜；
- 防碰评价；
- 姿态预测；
- 轨迹再规划；
- 实时数据和工程报警；
- 工程报告和轨迹图形。

系统管理不得新增以下独立管理入口：

- 工程文件管理；
- 轨迹版本管理；
- 防碰参数管理；
- 预测模型管理；
- 再规划方案管理；
- 工程报警中心；
- 工程连接器配置；
- 工程报告中心；

这些功能由工程模块按工程流程组织。系统管理只提供相应的权限、字典标签、审计记录和服务状态。

## 四、系统管理功能之间的关系

- 用户属于部门，可以关联岗位；
- 用户通过角色获得菜单和按钮权限；
- 角色通过工程数据范围获得井场访问范围；
- 工程页面读取系统字典显示名称；
- 平台主题控制通用界面样式；
- 日志记录用户、权限、配置和安全操作；
- 运行监控反映 Java、数据库、算法服务、GPU 和数据服务状态；
- 备份管理保护系统数据库、工程文件和模型文件；
- 个人中心只修改当前用户自己的资料和显示偏好。

系统管理实现完成后，工程师可以在授权范围内使用工程功能，游客可以在限定时间内访问演示功能，管理员可以管理人员、权限、显示规则和平台运行状态。
